Ice Cream Shop

תיעוד מלא, סקירת מצב והמלצות להמשך

פרויקט ASP.NET Core המבוסס על מבנה הדוגמה Weather Forecast ועל פרויקט חנות הפיצה של המורה.

סיכום קצר

הפרויקט כולל API לניהול טעמי גלידה, ממשק דפדפן, שמירת נתונים בקובץ JSON, middleware לסגירת החנות, Swagger ודוגמת Weather Forecast. המבנה הוא של ASP.NET Core עם Controllers, מודלים, שירות וממשק שירות.

מצב בדיקות: הבנייה האחרונה הצליחה ללא שגיאות ואזהרות. בבדיקות HTTP התקבלו תשובות תקינות מהאתר, מ-Swagger, מ-Weather Forecast ומ-API הגלידות. גם תרחישי CRUD ותגובה 503 כשהחנות סגורה נבדקו.
הערת נתונים: בזמן הסקירה, Data/icecream.json מכיל 3 טעמים, בעוד icecream.json שבשורש מכיל 4 (כולל Vanilla). השירות משתמש בקובץ שבתיקיית Data. לא העתקתי אליו מחדש את נתוני הפתיחה כדי לא למחוק שינוי שנעשה במהלך שימוש בפרויקט.

הפעלה

נדרש .NET 10 SDK. פותחים PowerShell בתיקיית הפרויקט:

cd C:\תכנות\core\all\dot-net\IceCreamShop
dotnet restore
dotnet run

בפרופיל הפיתוח:

  • Swagger: https://localhost:5001/swagger
  • ממשק החנות: https://localhost:5001/
  • Weather Forecast: https://localhost:5001/WeatherForecast
  • API גלידות: https://localhost:5001/IceCream

אפשר להריץ dotnet build כדי לבנות בלבד. הפורטים שמוגדרים בפרופיל הם 5000 ו-5001; אם אחד תפוס, יש לבחור פורט אחר. הכתובת 5099 ששימשה בבדיקות אינה בהכרח כתובת ההרצה הרגילה.

איך הפרויקט בנוי

המסלול של בקשת API הוא:

דפדפן / לקוח API
    → middleware לסגירת החנות
    → Controller
    → IIceCreamService
    → IceCreamService
    → Data/icecream.json

Program.cs רושם Controllers, Swagger ואת השירות IIceCreamService, ומגדיר את סדר ה-middleware. תיעוד Swagger פעיל רק בסביבת Development. כשהחנות פתוחה, בקשות לדף עוברות דרך static files ובקשות API ממופות ל-Controllers. המיקום של middleware הסגירה לפני קבצים סטטיים ו-Controllers גורם לו לעצור גם את ממשק החנות וגם את ה-API; Swagger נרשם לפניו.

נקודות קצה

שיטה ונתיבפעולה ותוצאה
GET /IceCreamמחזיר את כל הטעמים.
GET /IceCream/{id}מחזיר טעם בודד או 404 אם אינו קיים.
POST /IceCreamמוסיף טעם ומחזיר 201 עם כתובת הפריט החדש.
PUT /IceCream/{id}מעדכן טעם. מחזיר 400 אם מזהה הנתיב והגוף שונים, 404 אם לא נמצא, או 204 בהצלחה.
DELETE /IceCream/{id}מוחק טעם. מחזיר 404 אם לא נמצא או 204 בהצלחה.
GET /WeatherForecastמחזיר חמש תחזיות לדוגמה עם תאריך, טמפרטורה, פרנהייט וסיכום.

דוגמת גוף להוספת טעם

{
  "name": "Pistachio",
  "isDairyFree": false
}

השרת מקצה את ה-ID. השם מסומן כ-Required. ה-UI משתמש בנתיב /icecream; ASP.NET Core מנתב אותו לאותה פעולה.

נתונים והגדרות

  • IceCreamService קורא את Data/icecream.json בעת יצירת השירות.
  • כל הוספה, עדכון ומחיקה נכתבים חזרה לאותו קובץ.
  • השירות רשום כ-Singleton; רשימת הטעמים נשארת בזיכרון כל עוד התהליך רץ.
  • ShopClosed=false מאפשר את הבקשות; true מחזיר 503 וטקסט הסבר.
  • אפשר להגדיר ShopClosed גם כמשתנה סביבה ShopClosed=true; הגדרת סביבה גוברת על JSON.
  • לשחזור תפריט הפתיחה, יש להחליף את Data/icecream.json בתוכן העותק icecream.json. פעולה זו תחליף את הנתונים הפעילים.

JSON הוא אחסון לימודי פשוט, לא מסד נתונים. עריכה מקבילה, תהליך שרת נוסף או כיבוי בזמן כתיבה עלולים ליצור אובדן נתונים או קובץ חלקי.

מה בדיוק נוצר ושונה

  1. נוצר פרויקט IceCreamShop נפרד בתוך תיקיית dot-net, עם חלוקה ל-Controllers, Models, Services, Interfaces, Middleware, Data ו-wwwroot.
  2. הותאם מודל החנות: פריט Pizza הפך לטעם IceCream, והשדה GlutenFree הפך ל-IsDairyFree.
  3. נבנה API CRUD ו-UI סטטי שמתחבר אליו; הוספתי בדיקות תגובת HTTP והצגת שגיאות בצד הדפדפן.
  4. הוספתי middleware בשם ShopClosed, שמחזיר 503 לפני הטיפול בדף וב-API כשהחנות סגורה.
  5. נשמרה דוגמת Weather Forecast כ-Controller ומודל. נשמר מבנה Controllers/Routes של הדוגמה; תאריך הדוגמה הוא DateOnly והערכים נוצרים באמצעות Random.Shared.
  6. הפרויקט הוגדר ל-net10.0 כי בסביבת ההרצה היה מותקן .NET 10 בלבד, ללא runtime של .NET 8.
  7. גרסת Swashbuckle עודכנה ל-10.3.1 לאחר שגרסה קודמת הביאה תלות Microsoft.OpenApi עם התראת אבטחה. סריקת החבילות לאחר העדכון לא מצאה חבילות פגיעות.
  8. נוסף README באנגלית עם הוראות הפעלה, API ומפת הקבצים; דף HTML זה מוסיף תיעוד וסקירה בעברית.

זו התאמה של הדוגמה ולא העתקה מילולית של כל קובצי המורה: שם הפרויקט, שדות הנתונים, גרסת .NET, חבילת Swagger וממשק המשתמש הותאמו.

מה חסר / מה כדאי להשלים

עדיפותחסר או מגבלהמשמעות והשלמה אפשרית
חשוב עכשיו אין בדיקות אוטומטיות בפרויקט. בדיקות ידניות עברו, אך אין בדיקות שחוזרות אוטומטית אחרי שינוי. להוסיף פרויקט בדיקות עם בדיקות Controller/Service ובדיקת API.
חשוב עכשיו שני קובצי JSON שונים משמשים למטרות דומות. השירות משתמש רק ב-Data/icecream.json; העותק בשורש עלול להטעות. מומלץ לבחור מקור אמת יחיד ולתעד או להסיר את הכפילות.
חשוב עכשיו קובץ הנתונים הפעיל שונה מתפריט הפתיחה. בבדיקה נמצאו שלושה פריטים פעילים לעומת ארבעה בקובץ השורש. כדאי להחליט אם זו עריכה מכוונת; לא שוחזר אוטומטית כדי לא לדרוס נתונים.
לפי דרישת החנות מודל מוצר מצומצם. יש רק שם וסימון Dairy-Free. חנות אמיתית עשויה להזדקק למחיר, תיאור, גדלים, אלרגנים, רכיבים, מלאי וזמינות.
לפי דרישת החנות אין הזמנות או סל קניות. הפרויקט מנהל קטלוג טעמים בלבד; אין לקוחות, עגלת קניות, הזמנה, תשלום או מעקב משלוח.
לפני שימוש אמיתי אין בסיס נתונים או מנגנון כתיבה בטוח במקביל. קובץ JSON מתאים ללימוד. לשרת אמיתי מומלץ מסד נתונים, ולכל הפחות הגנה מפני עדכונים מקבילים ושמירה אטומית.
לפני שימוש אמיתי אין אימות משתמשים והרשאות. כל מי שמגיע ל-API יכול לנסות להוסיף, לערוך ולמחוק טעמים. יש להגדיר הרשאות לממשק ניהול לפני פריסה.
לפני שימוש אמיתי אימות קלט מוגבל. [Required] דורש שם, אך אין הגבלת אורך, נירמול/trim בצד השרת או כללי תחום למאפיינים.
שיפור אין טיפול שגיאות API אחיד או לוג תפעולי ייעודי. שגיאת קובץ/IO עלולה להפוך לתשובת שגיאת שרת כללית. אפשר להוסיף middleware לטיפול בחריגות, Problem Details ולוגים מתאימים.
שיפור אין מדיניות CORS, פריסה או תצורת Production מתועדת. באתר סטטי מאותו host אין צורך ב-CORS; אם ה-UI יופרד או תתווסף פריסה, יש להגדיר מקור, HTTPS, Secrets ותהליך פרסום בהתאם.
שיפור תיעוד אין תיעוד API מורחב של דוגמאות/שגיאות או מדריך בדיקות אוטומטי. Swagger קיים ומציג את הפעולות, אך כדאי לתעד דוגמאות, קודי שגיאה, כללי קלט ותהליך בדיקות.

מה אומת בסקירה

  • dotnet build לפרויקט הסתיים בהצלחה, 0 שגיאות ו-0 אזהרות לאחר עדכון החבילה.
  • בדיקת חבילות NuGet לא הציגה חבילות פגיעות במקורות שהוגדרו.
  • בבדיקת HTTP הנוכחית התקבלו 200 עבור /, /swagger/index.html, /WeatherForecast ו-/IceCream.
  • בבדיקות קודמות נבדקו הוספה, עדכון, מחיקה, 404 לפריט שנמחק ו-503 כשהחנות סגורה.
  • אין בפרויקט כרגע בדיקות אוטומטיות שמבצעות את התרחישים האלה בעצמן.
